## 换回自己的电脑：一天折腾实录

七月的最后一天，我从公司电脑切回了自己笔记本。

说起来不算什么大事——提了离职，东西搬回自己的设备。但真开始弄的时候才发现，事情比我想象的碎。从工作文件、浏览器书签、到博客的部署脚本和定时任务，每一样都要自己动手弄一遍。

记录一下今天干的几件事，留个底，以后再换电脑就知道怎么搞了。

### 第一件事：把博客从公司电脑迁移回来

我的博客（你现在看到的 resc.cn）跑在一台腾讯云服务器上，用的是 VitePress + 宝塔面板管理。原来那台电脑上有源码、部署脚本、还有一个定时发文的 cron 任务。

问题来了——OpenClaw 的工作空间和 cron 任务都存在本地的。换电脑之后，这些东西全部丢失，只能重新来过。

第一步是重新 clone 源码仓库：

```
git clone git@github.com:zxxstudio/resc.cn.git
```

deploy key 也得重新配，之前公司电脑上是存好的，这次从私有备份仓库里翻出来重新放回去。

最难搞的是 GitHub Token——旧的 Token 已经失效（401 报错），新建了一个，但只有 7 天有效期，过几天得记得去 GitHub 设置里删掉。

### 第二件事：重新安装依赖和部署环境

本地跑 VitePress 需要 Node.js 和 pnpm。还好新版 Node 安装比较顺利，直接从 nodejs.org 下就行，pnpm 一行命令装好：

```bash
npm install -g pnpm
```

依赖装好之后 build 一次：

```bash
node node_modules/vitepress/bin/vitepress.js build
```

二十多秒完成，没问题。然后部署到服务器，脚本用的是 scp 直传，服务器 IP、目录、SSH 密钥都在脚本里配好了，跑一次脚本就自动完成。

服务器用的是宝塔面板管理，Nginx 配置里早就把 www 和不带 www 两个域名都绑好了，切回来之后直接就能访问，不需要额外改配置。

### 第三件事：把 cron 任务重新建起来

最麻烦的是定时任务。之前每天下午五点自动写文章并发布的任务，换电脑之后全丢了。

还好备份仓库里有记录——我知道任务的内容和规则。把两个 cron 任务重新建好：

- **每天 17:00**：写当天文章（图文结合，封面用文章配图），自动 build → 部署 → push 到 GitHub
- **每天 23:00**：备份 cron 任务列表和文章索引到私有仓库

重建 cron 任务花了一点时间，主要是确认 OpenClaw 的 sessionTarget 和 schedule 格式不能填错。配置好之后试跑了一次，任务正常触发，文章成功发出。

### 第四件事：写今天的文章

定时任务设好了，网站也跑起来了。今天的文章是我手动补发的——因为定时任务下午五点触发的时候，旧电脑那边的任务已经没在跑了。

写什么主题呢？想了想，就写今天这一天的折腾过程吧。比起技术科普，记录真实做过的事更有意思一些。

以后每天的定时文章都会按这个思路来：写当天真正发生的事、真正解决的问题。不写那种"今天学了一个知识点"的流水账，也不写纯科普——那些留给专业博客，这个站点就记录生活里顺手折腾的东西。
